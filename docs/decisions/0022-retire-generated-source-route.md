# 0022 — Retire the custom generated-source route

Status: accepted on 2026-07-15 after the final request-0 allocation canary and
before any generated policy, safety, planner, progress, probe, or training
outcome.

## Context

The main scientific direction is not refuted. On the original frozen baseline
population, endpoint-free direct safe-progress actions exist for 17/17
branch-valid collision groups, and the privileged distributed flow edit passes
9/17 while frozen, random, the registered analytic edit, and the bridge pass
0/17. That establishes physical feasibility and partial privileged
steerability, but not learned-probe efficacy or transport to new groups.

ADR-0021 allowed one final controller-canonicalized canary for a custom,
non-Level-II retired source population. Slurm task `27614_0` ran at clean commit
`314772cb783295d9598e68f3c432b95b72202bdb` with the unchanged scientific config
SHA-256 `332c90fdb9e4560ab522e6333fbe5f0846d1c7caca9190f1730436036856f22a`.
It retained an outcome-blind rejection before settling or any research outcome:
`controller canonicalization requires the Panda robot`.

The rejected premise is concrete. SafeLIBERO's floor problem rewrites the
requested `Panda` robot to `OnTheGroundPanda`; that wrapper uses the Panda XML,
Panda gripper, and default Panda controller, but its runtime robot identity is
not the exact identity frozen by the final canary. The dependent CPU validator
`27615` therefore did not run. This is an apparatus/estimand failure, not
evidence that a clearance probe cannot steer a VLA.

## Decision

1. Fire the preregistered hard stop. Do not patch the robot-name contract, do
   not resubmit request 0, and do not run requests 1--9 or the generated R01/R02
   transfer ladder.
2. Do not train, calibrate, validate, or test a learned probe from this custom
   population. It produced no accepted source group.
3. Keep R04 blocked rather than converting the original 17 development groups
   into a claim-bearing learned experiment. Those groups have already informed
   feasibility, intervention design, and authorization; reusing them for model
   selection and final evaluation would not provide an independent test.
4. Preserve the positive baseline result precisely: the research idea remains
   plausible because privileged flow steering improved Safe-Progress Success
   from 0/17 to 9/17 against the registered controls. The unresolved problem is
   whether a learned scalar probe can recover a task-preserving direction on
   untouched groups, especially the four clearance-only and four progress-only
   oracle failures.
5. Resume only after obtaining a defensible independent source population:
   preferably the benchmark authors' generator / new official saved states, or
   a separately preregistered task expansion with untouched episode groups.
   For that population, rerun the shortest ladder: unsteered baseline collision
   prevalence, direct safe-progress existence, privileged-flow transfer, then
   probe labels and learning only if the privileged arm transfers.
6. The eventual decisive comparison remains paired by state, observation,
   policy noise, latent, and horizon: unsteered baseline, learned probe,
   equal-realized-norm random, strong time-structured analytic guidance, AEGIS,
   the closest reproducible constrained-flow method, privileged direction, and
   direct planner. Primary outcome is Safe-Progress Success; report collision,
   progress, false-safe rate, grouped uncertainty, and end-to-end inference
   latency separately.

## Consequences

No learned ECG model has been trained or evaluated, so there is no measured
probe improvement or latency advantage to report. The exact-endpoint failure
is already solved at the physical-feasibility level by endpoint-free actions;
the current root blocker is independent, transport-valid data rather than a
lack of safe actions. The original 9/17 privileged result supports continuing
the direction once new groups exist, but does not establish that learning is
necessary, better than stronger analytic/system methods, or faster than AEGIS.

There is no authorized next compute command in the present task-0 source route.
The next state-changing step requires a new source-population decision and
preregistration; until then, repository tests and retained failed artifacts are
the terminal handoff evidence.
